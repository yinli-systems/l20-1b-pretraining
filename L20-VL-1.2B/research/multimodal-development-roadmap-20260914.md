# L20-VL：从压缩机制实验走向实用多模态模型

研究日期：2026-09-14。状态：建议路线，未启动新训练；不修改现有冻结实验协议。

## 结论

继续使用自己的 1.100B 语言底座，但不要把“固定 49 个视觉 token、始终冻结语言模型、只做合成绑定题”当成整个模型的能力边界。建议产品目标是：**一个能看真实图片、读局部文字、指出证据、比较前后变化，并能在必要时放大检查的端侧视觉助手。**

先做好图像和短视频；语音接口可以后接，原生全模态训练暂缓。已有论文已经研究过指认、动态分辨率和视频，小模型做这些本身不是新颖性。研究贡献应集中在我们已有的弱点：视觉预算下降时，对象—属性—关系的绑定能否稳定保留，并推广到真实图片。

## 1. 现有证据决定了该补什么

以下来自本轮读取的本地协议和完成结果，不是本轮远程 GPU 遥测。

| 项目 | 已确认事实 | 对路线的影响 |
|---|---|---|
| 语言底座 | 1,100,048,384 参数；约 20B 预训练 token；上下文 2,048 | 不更换底座；不能直接照搬其他模型的长视频上下文配置 |
| 视觉编码器 | SigLIP2 B/16，224×224，196 个 patch token | 小字可能在输入缩放时就消失；只增加后续 token 数不能恢复原始细节 |
| 当前压缩 | 196 → 49 个视觉 token | 保留为省成本模式，不作为所有任务的硬上限 |
| Stage D IID family-joint | A49 75.03%，F196 74.99% | 当前受控分布中接近，不代表开放世界能力已经成熟 |
| Stage D OOD binding family-joint | A49 6.04%，F196 5.94% | 全 token 对照也很弱；问题不能全部归因于压缩器 |
| 训练与数据 | 已有受控合成实验；已从完整人工审核的 Open Images 目标中冻结 77 对/154 张 posture hard negatives，并完成 pair-atomic 5-fold 划分 | 该小集可筛选真实图机制，但远不足以支持通用 VLM 或最终确认性结论 |
| 真实图零样本 | Stage-D parent 在 target-crop 为 60.39%，true−paired-swap +20.78pp，95% CI [10.39,31.17]；CAVR crop 为 48.70%，且相对 parent -11.69pp [-18.18,-5.19] | 从 Stage-D parent 做真实图开发；合成 CAVR 保留为机制证据，不作为真实图父模型 |
| 冻结视觉 probe | SigLIP2 full/crop 5-fold 单图准确率为 94.81%/97.40%；pair-joint 89.61%/94.81% | 视觉信息已存在；当前首要瓶颈是 bridge/readout，而不是立即更换 encoder |
| 真实图 readout crossfit | 只训练 659,521 个 query-readout 参数后，marked/full/crop 样本外准确率 94.81%/88.31%/87.01%；相对 Stage-D parent 分别 +37.66/+35.06/+26.62pp，三个 95% CI 下界均 >0 | 冻结 query-CE recipe，转入新确认集；不在已见 77 对上继续调参 |
| bbox 辅助监督 | marked region top-1 相对 query-CE +46.75pp [37.66,55.84]，但 marked 答案 -4.55pp [-9.74,+0.65]、pair-joint -9.09pp [-19.48,+1.30] | 不把注意力可解释性误当答案增益；grounded arm 暂不进入确认 |

IID 与 OOD 行是不同评测集合，不应当作同一指标随训练的升降曲线。上述 family-joint 不是普通单题准确率，也不是公开 VQA 分数。Stage D 未通过既定确认性判据，但不等于模型没有开发价值。

本地依据：[协议](../protocol.json)、[完成结果](../evidence/stage-d-confirmation-summary-v1.json)、[真实图片审核](pixmo-cap-stage1-admission.md)。语言底座从零训练；视觉编码器使用已有预训练权重，因此不能称整个 VLM 全部从零预训练。

## 2. 能力建设优先级

### P0：真实图片基础能力，以及语言层的多模态适配

先覆盖对象、属性、数量、关系、简短描述和可核对问答。目标不是让模型对每张图生成长篇解释，而是能够稳定回答短而具体的问题，并真正利用图像。

冻结语言模型适合之前的机制隔离实验；开发通用能力时，应比较以下方案：桥接层训练、桥接层加语言层 LoRA、必要时再测试有限层解冻。采用同一数据、同一评测，并同时报告训练成本和纯文本能力保留。不能预设 LoRA 或全量训练必胜。[TinyLLaVA](https://arxiv.org/html/2402.14289v1) 对连接器、视觉编码器和训练方案的研究提供了可借鉴的比较框架。

加入一个很便宜的诊断：把正确场景描述作为文本输入，检查语言底座是否能答对相同问题。文本条件也错时，优先修语言任务能力；文本能答对、图像答不对时，再定位视觉编码、桥接或融合。这个文本上界仅用于诊断，不是正式评测中提供答案信息。

小模型不宜默认依赖冗长思维链。[SmolVLM 的消融](https://arxiv.org/html/2504.05299v1) 发现，所测试配方中过多长推理数据可能损害小型 VLM。对我们更合适的起点是答案监督、短证据和可验证中间结果；这不是“小模型永远不能推理”的结论。

### P1：Grounding——不仅回答，还能指出对象和证据

把“左边的杯子是什么颜色”扩展为“指出这个杯子的位置，再回答颜色”。初期可以采用归一化点或框的短格式，不必立刻添加复杂新解码器。训练中包含目标不存在、多个同类实例、遮挡和属性交换，避免学成见到名词就随便指一个对象。

这直接连接现有绑定实验与真实应用：截图按钮定位、文档字段定位、物体计数和关系判断。位置输出也能帮助检查模型是否看对了对象，但一个看似合理的框本身不能证明推理忠实。

[MolmoPoint](https://allenai.org/blog/molmopoint) 已将视觉特征选择用于指认，并拓展到图像、界面和视频。因此“加指点功能”是能力建设，不是独创声明。我们需要研究的是较小模型在较低视觉预算下的实例绑定稳定性，而不是复制其模型规模或直接引用其成绩作为预期。

### P1：按需高分辨率，优先读字、表格与截图

保留低分辨率全图概览，必要时从**原始图片**裁取高分辨率局部，再编码。不要仅把同一张已经缩小的 224×224 图片多分几个 token。

建议比较三种输入模式，先建立简单可靠基线：

| 模式 | 视觉表示 | 适用场景与限制 |
|---|---|---|
| 省成本 | 全图 49 token | 物体、粗粒度场景；小字不足 |
| 全 patch 对照 | 同一全图 196 token | 检查压缩损失；仍不能恢复缩放丢失的细节 |
| 多裁块 | 全图 + 4 个原图裁块，各 49 token，共 245 | OCR、局部细节；需要 5 次视觉编码，不能只按 245/49 估算总延迟 |

245 仅为视觉 token 数，不含分隔符、位置标识、问题和答案。当前编码器原生 224 输入，可先采用这种原生尺寸裁块，不直接冒用其他编码器的 512 原生输入能力。多分辨率模式需要相应训练，不保证同一未适配权重能自动使用新增裁块。

[LFM2.5-VL-1.6B](https://huggingface.co/LiquidAI/LFM2.5-VL-1.6B) 使用原生分辨率处理、分块和缩略图，说明这种工程路线已有成熟先例，但它的编码器与上下文配置不同。文档专项也值得借鉴 [Granite-Docling-258M](https://huggingface.co/ibm-granite/granite-docling-258M)：小型模型可以围绕结构化文档转换形成明确用途，不必先追求百科式全能。

当前编码器的最低风险升级对照是同尺寸的 [SigLIP2-B/16 NaFlex](https://huggingface.co/google/siglip2-base-patch16-naflex)：它保持 ViT-B 规模，但支持多分辨率与原生长宽比，并强化 localization/dense features。必须把它作为重新对齐的独立 arm，而不是直接把 224 bridge 权重套上去。先比较 224、NaFlex 固定 token 上限、原图裁块三种模式，才能分开“输入缩放丢失”“压缩丢失”和“语言读取失败”。

### P2：两图比较，再扩展到短视频

先做两张图的变化识别、对象对应与位置变化，再加入少量短视频帧。任务应要求真正比较，比如“哪个对象移动了”“谁先拿起杯子”，而不只是每帧独立描述。

以每帧 49 token 为例，8 帧占 392 个视觉 token，尚需计入时间标记、问题和输出，不能因此承诺长视频支持。在 2,048 上下文内控制片段和答案长度；延长 RoPE/上下文需要另行训练与保留测试。

[SmolVLM2](https://huggingface.co/blog/smolvlm2) 已有 256M、500M 和 2.2B 的图像/视频模型，证明紧凑视频路线值得研究，但不证明我们的底座可用同样成本达到其能力。评测至少包含反转帧序、打乱帧、只给最后一帧等对照，排除把静态线索当作时间理解。

### P2：会请求放大，也会承认看不清

把策略做成三个可测试动作：直接回答、请求一个裁块、无法可靠回答。先用有监督数据学会动作和格式，稳定后才考虑强化学习优化质量与成本。

[VisionThink](https://arxiv.org/abs/2507.13348) 已研究低分辨率起步、必要时请求高分辨率的机制，动态放大不是新点。我们的研究机会是：能否定位造成对象绑定不确定性的局部，并用少量额外视觉信息修复它。

比较固定预算、随机裁块、普通置信度裁块和候选方法。看准确率—延迟曲线、额外裁块比例、错误自信率与拒答覆盖率，不能用“一直放大”或“一直拒答”伪装成功。

### P3：端侧优化与语音

端侧优化先做参考精度，再比较 INT8/INT4 或混合精度；必要时让桥接层维持较高精度。分别检查 OCR、对象绑定、输出格式和文本能力。报告真实目标设备的端到端首 token 延迟、生成速度、峰值内存及冷/热启动，不能将 GPU MFU 或受控候选打分速度当作手机体验。

现有自定义视觉压缩器需要验证推理后端支持；其他模型能导出 GGUF/MLX，不代表我们的整个结构自动兼容。

语音方面，先接 ASR → 我们的 VLM → TTS，形成可用交互。这是语音接口，不是原生音频理解，也不能靠转录辨认所有环境声音。[LFM2.5-Audio-1.5B](https://huggingface.co/LiquidAI/LFM2.5-Audio-1.5B) 的原生音频设计涉及音频编码器、离散音频生成等额外组件；等图像路线稳定后，再评估音频输入到文本，而不是现在同时训练语音生成、全双工和视频。

## 3. 数据与训练：比再加一个模块更重要

1. **只使用已确认许可、来源与质量的训练记录。** PixMo 的已审 288 张样本目前仅供前向诊断；不能自动扩大为训练授权。之前 OCR 子集发现乱码的问题也不能因追求规模而忽略。某个子集被拒不等于整个数据家族不可用。
2. **真实图片为主，可验证合成为补。** 自行渲染的表格、界面、文本和受控场景容易获得正确答案，但要用真实图片单独检查迁移，不把合成分数当实际读图能力。
3. **先做一轮受控配方，而非宣称最佳配比。** 可把 50% 真实图片短描述/QA、20% 定位与绑定、20% OCR/结构化、10% 文本保留作为候选起点；按受监督目标 token 计量，并报告图片数和总输入成本。这个比例是待验证提案，不是文献证明的最优比例；没有合格数据时缩小试验，不用未审核数据补齐。
4. **教师答案不是事实。** 若采用大模型辅助标注，要求视觉依据和独立抽样；程序可判题优先使用确定标签。不要让已有 OOD 很弱的 F196 充当全能教师。
5. **效率围绕端到端吞吐。** 缓存仅适用于确定性且冻结的视觉路径；可训练视觉层或随机裁剪时不能复用不匹配缓存。按图像/裁块数量与文本长度分桶，正确屏蔽 padding、用户提示的监督损失，检查样本打包没有跨样本信息泄漏。每次优化都检查 loss/梯度或结果一致性，再测真实 L20 吞吐。

纯文本保留数据不是越多越好。SmolVLM 报告过特定文本数据混合带来的性能退化；应将其视为需要消融的超参数，而不是照搬大模型的回放比例。

## 4. 最值得投入的研究问题

**问题：小型 VLM 能否在有限视觉预算下，既稳定保留“谁具有什么属性”，又只在证据不足时购买必要的局部细节？**

这比泛泛宣称“做一个全模态 1B”更可检验，但仍是候选问题，不是已经验证的新方法。前一份 [绑定残差研究](innovation-review-binding-residual-20260914.md) 是可能的机制分支；只有它超过同数据、同预算的强普通交叉熵基线，才值得与自适应裁块结合。

把系统拆开做消融：普通连接器 / 绑定残差 × 固定输入 / 自适应局部输入。分别检查哪个部分提供增益，不让更大图片预算掩盖机制本身没有贡献。若简单训练方案已修复大部分缺陷，就接受这个结果，把研究重心转向真实任务与成本。

更具体的产品与研究共同目标应是：**“ground, answer, verify, zoom”**。先输出归一化 point/bbox，再给短答案；用错配图、空图和 target-crop 对照验证答案是否依赖正确证据；只有低预算证据不足时才请求原图局部。它比泛化聊天更容易在 1.1B 上形成清晰优势，也能自然延伸到 GUI、OCR、文档和短视频。动态裁块已有 [AdaptVision](https://arxiv.org/abs/2512.03794) 与 [Token-Efficient VLM](https://research.nvidia.com/labs/lpr/publication/tevlm2025/) 等先例，项目价值应来自固定成本下的绑定可靠性和严格因果验收，而不是宣称首创视觉工具。

“别人从未提出”不能靠若干搜索保证。指认、压缩、主动细看都有相邻工作；新颖性需要持续检查具体目标、机制和对照，低讨论热度也不能替代有效性。

## 5. 建议执行顺序

| 顺序 | 小规模可交付结果 | 再扩大投入的依据 |
|---|---|---|
| 1 | 冻结真实图片开发集：普通 QA、绑定、定位、OCR、两图比较、不可回答问题；加入文本上界诊断 | 确定主要缺陷发生在哪个环节 |
| 2 | 桥接层 vs 语言层适配试验，固定合格数据 | 真实任务有实质进步，且文本能力没有不可接受退化 |
| 3 | 49 / 196 / 多裁块输入与定位联合试验 | 分开确认缩放损失、压缩损失和定位收益 |
| 4 | 两图与短视频训练，自适应裁块策略 | 时序对照确实依赖帧顺序；裁块获得有用的质量—成本改善 |
| 5 | 目标端侧设备量化测试，再接语音接口 | 真实设备可用，量化没有毁掉刚获得的能力 |

开发阶段不需要每个尝试都跑完整确认性实验；先用小而干净的开发集淘汰无效路线，再对选中的方案做独立测试与置信区间。既避免为了极小差异耗光预算，也不把挑中的开发分数当最终结论。

现代外部对照至少纳入 [Qwen3.5-0.8B](https://huggingface.co/Qwen/Qwen3.5-0.8B)、[LFM2.5-VL-450M](https://huggingface.co/LiquidAI/LFM2.5-VL-450M)、LFM2.5-VL-1.6B 与 SmolVLM2。Qwen 卡片的 0.8B 是语言模型参数口径，比较时要补齐视觉组件和总参数；其他模型也要统一参数口径。公开排行榜分数只用于选择对照，不代替同协议实测。分别报告质量优先模式和受限成本模式，保留各模型官方处理方式并注明输入分辨率、视觉 token、输出预算和推理设置差异。

## 6. 暂不投入

- 从头重新训练视觉编码器，或立即重训更大的语言底座。
- 同时开展原生语音生成、长视频、图像生成和机器人动作模型。
- 在基本答案/动作格式尚不稳定时启动大规模 RL。
- 用“最高 MFU”“全模态”“世界第一 token efficiency”替代真实能力与用户延迟。

这轮已在单张 L20 上完成 77 对/154 张真实图的冻结零样本诊断、SigLIP2 pair-atomic 线性 probe，以及固定 5-fold 的真实图 query-readout 开发。readout 实验只训练 `659,521` 个新增参数，10 个 fold 共 1,920 optimizer steps，耗时 `227.46s`，峰值 allocated 显存 `4.06GiB`；语言模型、已有 LoRA、视觉塔与 49-token bridge core 均冻结。query-CE 已在该开发集上胜出，但没有发布，也不能称为通用 VLM 成绩；下一步必须用全新 sealed confirmation 验证，再决定是否扩大数据与可训练范围。
