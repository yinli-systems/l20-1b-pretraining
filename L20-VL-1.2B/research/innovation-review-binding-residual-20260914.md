# 1B 视觉模型下一步：什么值得称为创新，什么只是换名字

研究日期：2026-09-14。范围：当前 L20-VL-1.2B 的视觉绑定与 196→49 token 压缩，不是重新预训练语言基座。

状态：文献查重、已有结果复核与实验设计完成；本文候选方法尚未实现、训练或取得新模型结果。没有启动子代理，没有启动远端任务，没有修改旧实验、发布或推送仓库。

## 1. 结论先行

最值得押注的问题是：**能否用一个很小的、通过干预实验定位的绑定信息通路，让只有 49 个视觉 token 的 1B 模型可靠区分“看见了哪些属性”和“属性属于哪个物体”？**

我建议探索一个工作假设：**干预定位的绑定残差通路**，下文简称 IIBR（Intervention-Identified Binding Residual）。这个名字只是方便讨论，不表示已经发明、验证或查明全球首创。

这里有两个不同的目标：

1. **让我们的模型明显变好。** 优先补齐保持属性数量不变的交换训练；普通答案监督可能已经有效。这条路成本低，但“增加针对性数据”不是方法学首创。
2. **形成有研究价值的新贡献。** 证明一类绑定错误由一个可定位、可修复的低维信息通路造成；再证明有针对性的修复显著优于相同数据、相同计算预算下的普通训练和已有压缩修复方法，并迁移到真实图片。

不能承诺“别人绝对没提过”或“效果一定惊人”。截至检索日期，绑定机制、反事实训练、空间信息保护、残差校准、低秩 token 压缩各自都有工作。**可能的空白是它们之间一个可以被实验否定的具体机制，而不是把几个关键词拼在一起。**

我的选择理由不是“论文少所以容易中”，而是当前项目恰好具备便宜的机制实验条件：相同语言父模型、49/196 对照、可控场景生成器、反事实配对、失败样例、冻结评测器，以及单卡可承受的小模块训练。

### 2.1 一个重要且可以核对的训练分布差异

代码位置：

- [训练/IID 绑定构造](</Users/alice/Documents/ChatGPT/Pretraining 2/L20-VL-1.2B/generate_counterfactual_diagnostic.py:150>)：单独给目标换颜色或形状，全图相应属性的数量可能变化。
- [OOD 绑定构造](</Users/alice/Documents/ChatGPT/Pretraining 2/L20-VL-1.2B/generate_stage_d_holdouts.py:72>)：交换两个物体的颜色，颜色与形状的多重集合保持不变。
- [当前压缩器](</Users/alice/Documents/ChatGPT/Pretraining 2/L20-VL-1.2B/modeling.py:131>)：7×7 池化结果作为查询，全量 196 token 作为 attention 的 key/value，之后有残差与 FFN。

由此得到的是一个**待验证解释**：训练分布允许利用部分属性存在性/数量线索；交换测试要求识别属性所属对象，原来的线索不够用。代码证明训练和测试的构造不同，**不证明模型已经实际采用某个捷径**。需要 bag-of-attributes 基线、反事实控制和表示分析验证。

还必须注意：颜色数量不变不等于像素颜色直方图不变。相同 size 的圆、三角形、方形面积不同，交换颜色后某种颜色的像素面积仍可能变化。新的数据必须检查这一点，不能把符号层面的控制夸大成所有视觉统计都相同。

### 2.2 对创新方向的限制

- F196 同样失败，因此“压缩毁掉了绑定能力”尚未成立。
- 当前压缩器已经读取全部 196 token，因此“首次让背景参与压缩”也不成立。
- A 比 F 多 4,726,274 个压缩器参数；旧比较不是纯粹 token 数量因果实验。
- [Stage C](</Users/alice/Documents/ChatGPT/Pretraining 2/L20-VL-1.2B/evidence/STAGE_C_FINAL_RESULTS.md>) 的 teacher evidence-delta 方案对强基线为 -0.500pp，CI [-1.367, +0.400]，不能改个名字继续宣传有效。
- 五个种子是同一个语言/视觉父模型上的适配种子，不是五次独立预训练。
- 语言基座从零预训练不等于整套 VLM 从零训练；视觉编码器采用已有 SigLIP2 权重。

### 3.1 两个真正改变判断的查重结果

**首先，绑定方向增强已展示实质性效果。** Dual Mechanisms 的 v2 在 COCO-spatial 上报告最多约 22 个百分点整体准确率提升。其 v1 的 What'sUp 结果是另一设置，不能混用成同一结果；“修复约一半原错误”也不是“总准确率提升一半”。这说明机制定位可能值得做，但数值来自别人的 4B/7B 系统，不能直接预测我们的 1B。[论文 v2](https://arxiv.org/html/2603.22278v2)

**其次，保留背景与残差校准都已有近邻。** CaRe 已在固定输出 token 数下回注未选 token 的信息；token-role 工作也发现保留非 alive token 有时有利。因此仅实现一个 bypass、加一个 gate 或挑选背景 token，最多算工程变体。[CaRe 方法段](https://arxiv.org/html/2607.27700v1)、[token-role 研究](https://arxiv.org/abs/2608.04483)

本次检索没有找到一篇完全对应“通过受控属性交换定位一条可因果验证的小型绑定通路，在冻结小语言模型、固定 49 token 的条件下修复全量父模型也会犯的错，并隔离数据效应”的直接工作。**这只是当前检索的未发现，不是优先权证明。**

### 3.2 对“热度很低”的回答

视觉 token 压缩不冷门；反事实对齐与绑定也不能再叫无人关注。2026 年已有多项非常近的工作。

相对窄的交叉问题是：**低预算小模型中，绑定信息究竟“没编码”“传丢了”还是“没有被语言模型用起来”，能否在不增加序列长度的情况下定点修复？** “相对窄”是从本次文献覆盖作出的判断，不是引用计量结果。不能把新近论文暂时少引用解释成方向独特。

## 4. 真正值得测试的假设

### H1：失败是属性存在性与属性归属之间的表征/读取错位

模型可以对一张图里的颜色、形状分别敏感，却没有可靠的对象—属性对应关系。已测 OOD 现象与这个解释相容，但还可能是训练覆盖不足、视觉编码不足、评分格式偏置等其他原因。

最便宜的反证就是在相同交换数据上训练普通 CE。若它迅速达到高水平并跨几何、属性组合泛化，优先接受“训练分布不足”的解释，不强行发明一个深层机制。

### H2：可修复的绑定信息是低维、分布式的，而且通用 bridge 没有充分传递/利用

这里“低维”是未知量，不能预设成立。先测试 rank 16；只在开发结果支持时测试 rank 32。必须同时区分：

1. SigLIP2 的 196×768 特征中是否能解码对象—属性对应。
2. 49×768 压缩后是否仍能解码。
3. 投影成 49×2048 后是否仍能解码。
4. 修改这部分表示是否真的改变语言模型的正确答案，而不只是让 probe 分数上涨。

线性 probe 成功仅证明可解码；失败也不证明信息不存在，非线性读取可能仍可用。需要有界的小型非线性 probe 对照，且所有 probe 必须按新场景家族划分数据。

### H3：正确的低维通路可以修复，而非只模仿全量父模型

这是最有价值也最难的部分：监督来自渲染器可核验的对象状态与答案，不来自失败父模型的答案偏好。输入可以仍使用父视觉编码器特征，但不把 F196 的错误当作训练真值。

若成功，贡献应该是“发现了错误发生和可修复的位置，并通过低成本干预产生可泛化效果”，不是“在 1B 上复现一个大模型方法”。

## 5. 一个足够具体、可以被推翻的最小实现

### 5.1 推理时的结构

令 H∈R^(196×768) 为已有视觉特征；C 为现有 49-token 压缩器；B 为已有 projector；原输入为 Z₀=B(C(H))∈R^(49×2048)。

新增：

```text
U: [768, r]                         低维读取方向
HU: [196, r]                       每个原始 patch 的低维表示
S2D₂(HU): [49, 4r]                 每个 2×2 patch 按固定次序拼到通道
W: [4r, 2048]                      把低维信息写入语言模型输入
Z = Z₀ + S2D₂(HU) W               仍然只有 49 个视觉 token
```

S2D₂ 是空间到通道的重排；这一算子不是新发明，也不代表投影后的表示无损。初始 W=0，先保持原模型行为；U 使用非零初始化，不让两个矩阵同时零初始化。初版冻结语言模型、视觉编码器与原 bridge，只训练新增通路，避免以大量主体参数变化掩盖机制。

这个旁路保留所有空间频率，不先假设绑定只在高频中。后续可在机制实验中拆解局部均值与均值残差，但不能先把背景低频信号丢掉、又宣称保护了背景绑定。

按不带 bias 的两次线性映射计算：

| r | 新增权重数 | 每张图新增矩阵乘 MACs | 说明 |
|---:|---:|---:|---|
| 16 | 143,360 | 8,830,976 | 约 0.143M 权重 |
| 32 | 286,720 | 17,661,952 | 约 0.287M 权重 |

这是结构公式，不是实测 latency；不含训练辅助头、归一化、张量重排、kernel launch 和 backward。它不增加 LLM 序列长度或 KV token 数，也不要求第二次视觉编码。仍需在真实实现中测延迟与峰值显存。

该形式本身非常接近低秩适配加空间重排，**不能靠这个公式主张新颖性**。

### 5.2 什么使这个候选值得研究

重点是 U 的识别与验证，不是新造一个残差层。

构造一对 H_b、H_s：两张图包含相同对象、颜色数量、形状数量与几何，只改变两个对象的属性归属。设 t 为符号场景中这个已知交换，Q 为一组同时包含受影响与不受影响问题的集合。

正常分支：

`Z_b = B(C(H_b)) + S2D₂(H_b U) W`

交换低维通路，但保留 b 的原 bridge：

`Z_{b←s} = B(C(H_b)) + S2D₂(H_s U) W`

训练要求 Z_{b←s} 对不同问题给出符号交换后的正确答案，包括应该翻转的问题与应该不变的问题。最小目标可以是：

`L = L_answer(real images) + λ L_answer(low-dimensional interchange)`

这属于 IIT 思路在特定旁路上的应用，**不是一个新的通用因果损失**。先用开发集固定 λ；不引入多项新的 margin、teacher delta、RL rollout 或一大批超参数。[IIT 的原始方法](https://proceedings.mlr.press/v162/geiger22a.html)

潜在新贡献仅在以下证据同时出现时成立：

- 干预训练比完全相同旁路、完全相同数据的普通 CE 更有效。
- 该低维通路的交换会选择性改变对应对象的答案，而不会让所有回答无差别翻转。
- 随机方向、相同维度的 PCA、普通位置编码、仅增参数都解释不了效果。
- 真实图片或未见对象组合上仍然存在效果；不只是记住渲染器的属性表。
- 加上这条通路后，49-token 模型可超过同数据适配的 196-token 基线，而非只超过没有再训练的旧 F。

### 5.3 这个设计可能完全失败的原因

1. 1B 父语言模型没有足够的对应关系读取能力；只改输入不够。
2. 视觉特征本身丢失细节，任何旁路都无法凭空恢复。
3. 当前 C 的全局 attention 已经把信息传好了，问题只是数据覆盖。
4. U 不包含独立的绑定变量，只是另一个足够拟合合成题目的特征通道。
5. 跨图激活交换产生离流形输入，模型学会识别干预伪影。
6. 原 projector 的归一化、旁路尺度或训练不稳定引起表面提升。
7. 普通低秩 CE 或 CaRe 一样好，无法建立方法贡献。

这些不是做完后补充的免责声明，而是决定是否继续投入的检查项。

## 6. 数据必须服务于识别问题，而不只是增加数量

### 6.1 最小问题矩阵

例：原图为“红圆、蓝方、灰三角”；交换后为“蓝圆、红方、灰三角”。

| 问题 | 原图 | 交换图 | 训练中要求 |
|---|---|---|---|
| 圆是红色吗？ | 是 | 否 | 正确改变 |
| 方形是蓝色吗？ | 是 | 否 | 正确改变 |
| 图里有红色物体吗？ | 是 | 是 | 正确保持 |
| 三角形是灰色吗？ | 是 | 是 | 正确保持 |

同一对图片支持多个问题，可复用冻结视觉特征；但是语言模型仍需处理对应的不同问题，不得把视觉缓存复用宣传成整个训练成本不随问题数增长。

训练和评测均包含 yes/no 平衡、反向提问、不同措辞、颜色/形状各自存在性题、真正的归属题以及少量旧能力 replay。场景 ID、文件名、family 编号、对象 oracle 不作为模型推理输入。

### 6.2 新划分，而不是反复利用旧 OOD

旧 Stage D 测试已被用于提出假设，保留为历史/回归证据，不再称下一轮“完全未见”的最终测试。

新数据按完整 scene family 分组；从一开始分别冻结 train、mechanism-dev、selection-dev 与 final-test。单纯换随机种子不够，应包含：

- 训练未见的属性组合，而各原子属性已经出现。
- 对象数量变化，以及未见的布局、尺度、背景。
- 训练中的两对象交换与测试中的多对象循环交换，单独报告这个外推难度。
- 另一种渲染风格或真实对象裁剪合成，避免只有一个生成器。
- 像素颜色面积、位置与对象面积的控制；至少显式报告不能完全匹配的统计。

标签来自图像实际渲染后的核验，不只检查符号字典。必须有生成器单元测试、图片抽查、去重和 family 划分检查。

### 6.3 真实图片验证

优先选择定位到“属性属于哪个实例”的外部任务，而不只是总体 VQA 得分。InstaBind-Lite 提供实例来源相关的错误分类，是候选外部检验；COCO-spatial / What'sUp 可检验空间读取，但不能替代同类实例属性绑定。[InstaBind-Lite](https://arxiv.org/abs/2608.16805)、[空间绑定论文的数据设置](https://arxiv.org/html/2603.22278v2)

这里只完成了论文与任务适配判断，尚未完成这些数据的下载、许可、样本可获取性或与现有模型训练数据的重合审计。开始运行前必须补齐；不能现在就保证两天内完成全部真实图评测。外部测试不用于 U、λ、rank、prompt 或 checkpoint 的选择。

## 7. 省 GPU 的顺序：先证伪，再扩大

### E0：用新开发集定位失败，先不训练主体

检查候选顺序、batch 一致性、图片哈希、标签、预处理与 image-to-feature 对应关系。在 196 特征、49 特征、projector 输出上做小 probe，并分别测试对象区域、区域加背景带、全图特征。

采用真实像素编辑作为控制；只有 probe 可解码还不够，继续做选择性激活修补与随机方向对照。背景区域不能随意视为“无信息区域”，冻结 ViT 特征可能已全局混合。[绑定机制研究](https://arxiv.org/html/2603.22278v2)

判定：

| 观察 | 下一步 | 不能说的话 |
|---|---|---|
| 简单 CE 交换训练就解决，并有外推 | 采用简单训练，研究数据覆盖规律 | “新残差机制带来提升” |
| 196 可用，49 不可用 | 测保真旁路及强压缩基线 | 未测之前认定 pooling 是原因 |
| 49 可解码但输出不用 | 测读取/输入对齐修复 | 把 probe 成功等同因果使用 |
| 196 与49都无法可靠解码 | 检查更早视觉层或编码器适配 | 继续宣称压缩修复足够 |
| 低维干预不选择性、随机方向同样有效 | 停止绑定子空间主张 | 把激活幅度变化包装为绑定机制 |

### E1：必须有的比较

不是同时启动十几种新方法。先两种适配种子的开发筛查，只保留能改变结论的对照：

| 对照 | 目的 |
|---|---|
| 现有49模型 + 新交换数据 + 普通 CE | 判断收益是否只是补数据 |
| 匹配196模型 + 同数据 + 普通 CE | 避免再次比较“训练过的学生”和“没训练的老师” |
| 同一新增旁路 + 普通 CE | 隔离干预目标的独立价值 |
| 同一新增旁路 + 干预训练 | 待验证候选 |
| 固定随机 U / PCA U 的等维度旁路 | 排除额外容量或任意残差解释 |
| 开发筛选出的一个最近邻：方向增强或 CaRe | 排除已知简单方法已足够 |

空间重排/位置编码基线先小规模筛查；如果很强，应进入最终对照，不为了保留新方法优势而移除。

同数据不等于同计算：含交换分支的方法多了一次语言模型前向/反向。必须同时报告相同样本暴露量与相同 GPU 时间的比较，让普通 CE 可以利用相同时间增加训练。只对齐 step 数会给新方法额外预算。

不能把破坏标签正确性的 shuffled-pair 训练当作唯一负对照。使用相同图自身的 no-op 交换、正确符号标签下的无关属性交换、随机子空间交换，分别检验干预构造、选择性与额外计算效应。

### E2：只确认开发阶段选定的方案

固定候选、rank、λ、学习率、训练步数与格式后，才运行五个配对适配种子和新的封存测试。若需要讨论纯 token 数效应，再增加参数/结构匹配的196-token变体；否则只称 package-level 比较。

统计单位仍为 family，真实图任务为原始 image/instance-group；不能把同图多个问题或五个种子当成完全独立样本。配对 bootstrap 保留变体依赖；需要推广到适配随机性时同时报告种子维度。主要比较预先指定，其余是探索性，不在看到结果后挑最窄 CI。

### E3：确认是不是有用，而非只会做合成题

报告真实图任务普通准确率、绑定特异错误、无效生成、拒答/解析率及实例错配来源。加入短答案自由生成，避免所有效果都依赖 yes/no 候选评分。

计时分别测图像预处理、视觉编码、bridge、prefill、固定长度 decode；相同 batch、精度、图片和输出长度，独立 warmup、ABBA 顺序。BF16 快速开发可以，但最终需验证 batch/candidate 顺序敏感性，保留与旧 FP32 评分的差异记录。

## 8. 什么效果才值得称为“惊人”

以下是**拟议立项目标，不是预计结果，也尚未作为新实验协议冻结**：

| 层级 | 目标 | 可以支持的表述 |
|---|---|---|
| 修复有效 | 新 OOD 绑定 family-joint 相对冻结旧49模型提高 ≥20pp，同时普通逐题准确率提高 | 当前模型的特定失败得到明显改善 |
| 有方法增益 | 相对同数据同计算的最强基线提高 ≥5pp，配对95% CI下界>0 | 有额外方法价值，而非只是数据价值 |
| 有可信能力 | 新 OOD family-joint 达到 ≥70%，未见组合/布局分别不崩溃 | 绑定从偶发成功进入较可靠区域 |
| 有实用价值 | 一项真实图绑定主指标显著改善；通用回归不超过预先约定损失；实测额外延迟≤10% | 高效小模型的可迁移改进 |
| 有较强研究价值 | 选择性因果修补、强对照、真实图迁移、第二视觉/语言骨架重复成立 | 一个有机制解释和适用边界的发现 |

从历史 6% 到 26% 看起来是四倍多，但仍远谈不上可靠；比旧模型提高与比强基线提高是两回事。若普通 CE 已经达到 80%，候选达到 82%，那不是上述意义上的巨大方法突破。

同样，某个绑定任务超过一个更大的模型，不等于全面超过它。文本知识、推理、代码、对话等能力必须单独测，不能从视觉绑定结果推断。

## 9. 单卡预算与停止条件

历史 Stage C 的49-token答案训练为 875 steps / 801.95s；这是已有特定小数据、冻结主体、缓存路径下的测量，不是任意新数据的速度保证。Stage D 20次评分又用了3.41 GPU小时。多问题和干预训练都会改变新成本。

建议先设一个不超过24 L20 GPU小时的**分阶段预算提案**，并非本轮已获准或已启动的作业：

| 阶段 | 建议上限 | 达不到条件时 |
|---|---:|---|
| E0 数据/表示/干预定位 | 2 GPUh | 原因不支持旁路就停止该机制方向 |
| E1 两种子开发与强对照 | 6 GPUh | 不优于普通 CE 或简单已有方法就不扩种子 |
| E2 选定方案确认 | 10 GPUh | 按冻结协议报告正负结果，不反复重选 |
| E3 外部图与计时预检 | 6 GPUh | 下载/许可或运行成本不符则另行估时，不强行承诺完成 |

真正 ETA 应在新代码完成后，用至少100个稳定 step 与少量完整评测外推，再加数据准备和验证时间。24 GPUh不是24小时墙钟交付，更不是两天一定得到论文级结果。

工程上优先复用冻结视觉编码器缓存，记录 image SHA、encoder revision、预处理配置与dtype；按场景批处理多问题，缩短无效 padding。不要用 MFU 高低判断这个小模块方案是否有效：缓存视觉、小桥接训练的端到端瓶颈与原1B文本预训练不同。报告图/秒、问题/秒、GPU小时到达目标质量与内存，比套用6ND的MFU更有意义。

## 10. 与近期近邻究竟差在哪里

| 最近邻 | 不能冒领的部分 | 本候选必须新增的证据 |
|---|---|---|
| Dual Mechanisms | 绑定来源定位、背景分布、方向增强 | 在当前小模型中定位失败；不是复制已有增强就称新方法 |
| CaRe | 固定长度下回注残余视觉信息 | 标签可核验的绑定干预识别；证明它优于通用校准 |
| LRCP | 低秩结构和投影残差 | 因果有用的方向不等于高方差/大重构残差方向 |
| IIT | 隐表示交换与符号反事实监督 | 严格输入预算下的可部署小通路，以及对应收益/机制 |
| SIVA-RL | 干预之后选择变化或不变 | 不依赖失败策略判断语义；用已知场景变化检验选择性，而非仅policy reward变化 |
| 数据增强/普通CE | 新交换样本与答案监督 | 相同数据暴露、计算和容量对照后的额外价值 |

“1B、49 token、L20”只是实验条件，不足以在这些工作之外自动生成新颖性。真正的论文论点必须是新机制或可泛化的新规律；如果最后只有工程收益，就如实称工程收益。

## 11. 检索记录与未解决问题

使用的查重组合包括：

- visual token compression + binding / background / spatial information
- counterfactual visual alignment + sensitivity / invariance
- interchange intervention training + vision / binding
- token pruning + token roles / residual calibration
- low-rank visual tokens + residual / pixel unshuffle
- object-centric tokenization + compositional generalization

沿最接近的论文查到了 IIT、对象中心绑定、视觉 Binding ID、Dual Mechanisms、CaRe、LRCP 与 token-role 保护。过程中“仅保留背景”和“仅增加残差”两个宽泛候选因为近邻重叠被降级；“敏感/不变双 loss”也因为 SIVA-RL 与旧项目负结果而不作为主创新。

仍未解决：

1. 当前 SigLIP2 与1B模型中是否存在可以实用地识别的低维绑定方向。
2. 旧 OOD 崩溃主要来自数据分布还是结构/优化。
3. 少量合成干预能否迁移到真实多实例图片。
4. 固定49 token旁路与最新方法比较后是否仍有足够差异。
5. 检索索引遗漏、尚未公开的工作及不同术语下的重叠。

因此当前结论是：**这是值得做小规模证伪的研究候选，不是已经找到“全球无人提出、必定惊人”的答案。**

## 12. 最终建议

把第一步定为“查明并修复属性归属”，不要再以压缩率或非常小的均分差异作为主故事。先运行可解释的普通训练基线；有必要时才进入干预定位的小型绑定残差通路。

如果只有数据改变有用，我们拿到一个更好的模型和明确的失败解释；如果特定低维通路在强基线、真实图与干预验证下都成立，才有机会形成一个真正有分量的发现。**新意来自无法被更简单解释替代的证据，而不是新方法名字。**
